# 06-speaker-frames · 说话人静帧预处理

为 `annotation_pool_3500.jsonl` 的每条样本产出一张「目标说话人」静帧，
供 05-annotation 在标注页常驻提示「按这个人标注」。这张图只用于身份识别，不是被评定的材料。

**最终交付：3440 条，全部 status=ok。** 另有 60 条经人工判定画质不可用或说话人全程未露脸，
已剔除并列入 `out/discarded.jsonl`，供 05-annotation 从标注池排除。

所有 meld / mustard / chsims 条目都经过两道独立判据交叉验证，其中 248 条存疑样本
经人工看视频逐条复核（结论见 `human-review-report.md`）。

## 产出

```
out/
  frames/<sample_id>.jpg     裁切好的说话人面部（512×512）
  manifest.jsonl             每行一条，下游契约
  facescan.jsonl             中间产物：逐条人脸扫描结果与分桶
  embeds.npz / gallery.npz   中间产物：人脸特征与角色原型库
  verify.jsonl               中间产物：Gemini 复核结论
  review/index.html          人工核对联系表
```

`manifest.jsonl` 每行：`sample_id / source / speaker_name / frame_path / source_time /
bbox（原视频坐标系 [x,y,w,h]）/ method / confidence / status / note`，
跑过复核的条目另有 `verify` 与 `verify_confidence`。

## 各来源怎么处理的

| 来源 | 条数 | 方法 | API 成本 |
| --- | --- | --- | --- |
| mosi | 521 | 本地选帧（独白单人，相似度中位 0.95） | 0 |
| iemocap | 877 | 本地选帧（clip 已按说话人裁成单人画面） | 0 |
| meld | 920 | 角色人脸库全帧匹配 + Gemini 复核，配角走 Gemini | 约 $0.15 |
| mustard | 263 | 同上 | 约 $0.09 |
| chsims | 919 | Gemini asd（视频 + 标注参考帧）+ 第二道唇动复核 | 约 $2.62 |

总计约 **$3.0**。

## 设计要点

**按画面人数分流，不按数据集分流。** 先做一次全量本地人脸扫描，把 3500 条分成单人 2643 /
多人 855 两桶。iemocap 和 mosi 全部落在单人桶，1398 条一分钱不花。

**meld / mustard 用角色人脸库，不逐条问模型。** 这两个来源说话人姓名已知，
而单人桶样本「一张脸 + 已知角色名」本身就是带标签的人脸库，不用手工标注也不用调 API 建库。
识别用 OpenCV 的 SFace，和检测用的 YuNet 同属 opencv_zoo 一套，YuNet 的五点关键点
正好是 SFace 对齐所需的输入，不引入新依赖。

建库时按角色聚类取最大簇当原型：单人桶的标签本身有噪声——「反应镜头」
（画面是听话人特写、说话人在画外）会把错的脸挂在说话人名下——聚类能把这类离群点滤掉。
实测 579 张入库人脸里离群 71 张（12.3%），目视核对 15 张确认 14 张是真的另一个人。

**匹配时搜全部 9 个扫描帧，不只看一帧。** 单人桶的反应镜头问题不是「选错了脸」
而是「说话人压根不在这一帧」，拿原型搜全帧，说话人第 7 帧才露脸就用第 7 帧。
实测相对单帧 largest-face 纠正了约 17% 的条目。

**模型只做单选，不输出坐标。** 送给 Gemini 的是一张已用彩色框编号标好人脸的参考图，
问它「目标人物是几号」。这样绕开了归一化 0–1000 bbox 的换算与坐标顺序问题，
判别任务也从「定位」降级为「单选」。过肩镜头下说话人可能不在某一帧，模型答 0 时自动换帧重问，最多 3 帧。

**复核必须换一种问法，否则没有意义。** 判别阶段问的是「从编号框里选一个」——
那是多选一，模型会硬选；复核阶段改成二元验证，答不上来可以说 no/unsure：
meld/mustard 问「这张脸是不是角色 X」，chsims 问「说这句台词的是不是这张图里的人」。
实测 chsims 的 919 条里有 47 条（5.1%）被第二道判据否定，meld/mustard 上则抓出 137 条。

**Gemini 复核是独立的第二道判据。** 对 method=facelib 的条目，人脸库比对的是角色原型的
几何特征、Gemini 靠的是对角色的先验认知，两条判据互不依赖，都认同才算确认。
对 method=gemini 的条目，复核问的是同一个模型，不构成独立判据，但仍抓得住过度自信——
实测配角上「判别阶段给 0.95 硬选一个、复核阶段说这不是本人」的自我矛盾有 90 条。

## 门限是怎么定的

人脸库匹配门限先用留一法在 `out/embeds.npz` 上标定（同人相似度均值 0.710 / 异人 0.154），
再用全量 1182 条的复核结果回校。按相似度分层的「判非本人」率实测：

| 相似度 | 0.28–0.40 | 0.40–0.50 | 0.50–0.60 | 0.60–0.70 | 0.70+ |
| --- | --- | --- | --- | --- | --- |
| 判非本人 | 41.2% | 30.0% | 10.7% | 2.7% | 3.0% |

据此 `ACCEPT` 从最初的 0.40 上调到 0.55。低于 0.28 视为「目标人物整段不在画面」，交 Gemini 兜底。

## 数据集映射的坑

- **iemocap 的 clip 已按说话人裁成单人画面**，不是双人固定机位，无需性别规则或左右位置推断。
- **iemocap 的 mp4 容器虚报帧数**（声称 266 帧实际只有 52 帧可解码），必须用 `grab()` 数真实帧数。
- **不能用 `cap.set(CAP_PROP_POS_FRAMES)` 定位**，这批素材上大量失败，只能顺序解码。
- **chsims 的 clip_id 长度不一**（`0003` / `00014`），还有 `00008_0` 这种带后缀的，
  必须以 `ch-sims-interface.csv` 建索引，不能用正则拆 `sample_id`。
- **mustard 横跨 BBT / Friends / Golden Girls / Sarcasmoholics 四部剧**，
  剧名只在 facescan 的 `extra` 里（manifest 按契约不带 extra），传错剧名会让复核误判率从 9% 飙到 41%。

## 用法

```bash
export GEMINI_API_KEY=...      # 只从环境变量读，不落盘
./run.sh all                   # 完整流程
./run.sh report                # 查看进度
```

也可以单步跑，见 `run.sh` 顶部注释。小样本验证用 `--limit N --out /tmp/xxx.jsonl`，
不会污染正式 manifest；`./run.sh gemini --dry-run` 先看请求数与成本估算。

## 人工核对

打开 `out/review/index.html`，一屏铺 200 张图，点一下把认错人的标红，
`导出 rejected.txt` 存下来（标记存 localStorage，中途关掉不丢）。
`needs_review` 自动排在每个来源的最前面，`note` 里写明了是「两个判据吵架」
还是「模型自己打自己脸」，扫视时能分轻重。

chsims 的存疑条目左上角有「唇动」按钮，点开是逐帧嘴部对照条（每行一帧，列为左起第 N 人，
绿框是流水线选中的人）。**判断谁在说话不能看单帧**——说话的人可能恰好闭嘴，
没说话的人可能因表情恰好张嘴，只有把连续帧的唇形铺开才看得准。

驳回后重跑：

```bash
python3 src/requeue.py out/review/rejected.txt   # 从 manifest 摘出，原文件自动备份
./run.sh gemini --bucket all                     # 换方法重跑这些样本
```
